# 结果总表与高光参数口径

## 1. 统计口径

### 1.1 split 缩写

- `uu`: `unseen_object_with_unseen_envir`
- `us`: `unseen_object_with_seen_envir`
- `ra`: `unseen_object_with_random_area_light_condition`
  这里也可对应此前口头说法里的 `ua`，本文统一记为 `ra`
- `tu`: `training_object_with_unseen_envir`
- `train`: `train`

### 1.2 均值定义

本文表中的 `Mean` 默认指 **held-out 三项均值**：

`Mean = (uu + us + ra) / 3`

也就是说，`tu` 和 `train` 不进入这个均值，只单独列出。

### 1.3 关于 SSIM / LPIPS

这批 run 的 `SSIM / LPIPS` 实际上已经写进了 `wandb-summary.json`，只是 key 名不是大写的 `SSIM/LPIPS`，而是：

- `ssim_loss/<split>`
- `lpips_loss/<split>`

因此下表已经补齐 `SSIM Mean / SSIM(uu/us/ra)` 和 `LPIPS Mean / LPIPS(uu/us/ra)`。

说明：

- `SSIM Mean` 同样按 held-out 三项均值计算，即 `(uu + us + ra) / 3`
- `LPIPS Mean` 也按 held-out 三项均值计算，数值越低越好

### 2.1 结果口径说明

- 如果只看 **clean ablation 主链**，应使用：
  - `NG baseline`
  - `abl00_base`
  - `abl01_imgspace_fixed`
  - `abl02_quantile`
  - `abl03_blur`
  - `abl04_relative`
- `abl05_full_main` 当前不纳入最终主表，因为本地未整理到完整 summary。
- `spuru_hyblite_a / spuru_cosine_lowlr_a / spuru_freqsplit_a` 应视为 **follow-up enhancement branch**，不放进 clean ablation 主链。

### 2.2 当前最重要的结论

- `spuru_cosine_lowlr_a` 是目前**唯一明确 5/5 全面超过原始 NG baseline** 的 finished run。
- `spuru_hyblite_a` 属于明显 trade-off 版本：
  - `ra / tu` 提升明显
  - 但 `uu / us` 不稳
- `abl03_blur` 和 `abl04_relative` 是 clean ablation 主链里最稳的两行，其中：
  - `blur` 证明了 blur-for-threshold estimation 的正贡献
  - `relative` 是在 `blur` 基础上的小幅 refinement，而不是压倒性跳变

## 4. 建议的最终表格口径

### 4.1 对外主结果表

只保留：

- `NG baseline (7cn19b1e)`
- `spuru_cosine_lowlr_a`

如果 `spuru_freqsplit_a` 最终跑完且更强，再替换或并列。

### 4.2 方法消融表

只保留：

- `abl00_base`
- `abl01_imgspace_fixed`
- `abl02_quantile`
- `abl03_blur`
- `abl04_relative`

不要把 `spuru_hyblite_a`、`spuru_cosine_lowlr_a` 和 `spuru_freqsplit_a` 混进 clean ablation 主链。

### 4.3 附加增强实验

单独放：

- `spuru_hyblite_a`
- `spuru_cosine_lowlr_a`
- `spuru_freqsplit_a`

这样能把“方法消融”和“为了打赢 baseline 的后续增强”清楚拆开。

## 5. 当前最推荐的主模型

在 `spuru_freqsplit_a` 尚未完成前，当前主模型应优先使用：

- `spuru_cosine_lowlr_a`

理由：

- 是目前已完成 run 中唯一 5/5 全面超过原始 NG baseline 的版本
- 改动最克制
- 不引入 probe/hybrid 的额外论文叙事负担

## 6. 方法章节的补充口径建议

### 6.1 主方法

正文主方法仍建议收敛为：

- `foreground-mask-aware adaptive highlight supervision`

更具体地说，就是以下四个稳定、且已经被 clean ablation 支撑的模块组合：

- 前景掩码优先的监督范围限定
- 前景内分位数高光阈值
- 仅用于阈值估计的轻模糊
- image-space highlight guidance

### 6.2 不建议作为正文主方法补充的分支

当前不建议把下列分支写进正文的方法主线：

- `light probe / illumination probe`
- `latent highlight probe / hybrid probe distillation`

原因是：

- `spuru_hyblite_a` 虽然把 `ra/tu` 拉高了，但 `uu/us` 变差，属于明显 trade-off 版本
- probe 分支没有出现在当前最强模型 `spuru_cosine_lowlr_a` 中
- 如果把 probe 写进主方法，会让正文的叙事从“稳定高光监督”偏向“额外条件建模”，反而削弱当前已经成立的主线

因此 probe 更适合放在：

- 附加实验
- Appendix
- 未来工作

### 6.3 更适合作为正文补充方法点的内容

如果方法章节希望在主方法之外再补一个次级技术点，当前更合适的是：

- `optimization-stabilized training recipe`

也就是：

- cosine scheduler
- 更低的学习率
- 更稳的 late-stage optimization

它不应被包装成核心创新，但可以在方法实现或训练策略小节中解释：

- 为什么相同的高光监督在不同优化轨迹下会出现明显性能差异
- 为什么 `spuru_cosine_lowlr_a` 能在不改高光模块定义的前提下 5/5 全面超过 baseline

### 6.4 如果频域分支最终有效，如何放置

`spuru_freqsplit_a` 对应的 frequency-separation auxiliary branch 更适合作为：

- 正文中的 optional extension
- 或者正文主方法后的一个轻量增强模块

它比 probe 更适合和主方法并列讨论，原因是：

- 它仍然服务于“稳定高光监督”这个主问题
- 它没有引入新的条件接口或新的推理路径
- 它在叙事上更像对 image-space supervision 的结构化补充

所以当前最稳的写法是：

- 主方法：`foreground-mask-aware adaptive highlight supervision`
- 次级补充：`frequency-separated auxiliary supervision`（前提是最终结果成立）
- probe / hybrid：附加实验，不进入正文主线
