## 3. 论文主问题定义

目前最适合投稿的不是“Neural Gaffer 的若干训练技巧优化”，而是下面这个更清楚的问题：

**现有 diffusion-based object relighting 在 specular / area-light 条件下，高光监督不稳定，尤其容易在宽而软的高光波瓣、随机面光源条件和白背景前景裁剪下出现失败；我们提出一种 foreground-mask-aware relative highlight guidance，在不增加推理复杂度的前提下，稳定高光监督并提升 object relighting 泛化。**

这一定义有 3 个好处：

- 它把工作聚焦到一个具体 failure mode，而不是泛泛地说“提升 relighting”
- 它和你现在的代码改动是对齐的，不需要额外发明一个完全不同的新架构
- 它天然允许把 `ecommerce / official / 3D-FUTURE` 组织成跨域 object-relighting benchmark

## 4. 论文主方法与辅方法

### 4.1 主方法

论文主方法应定为：

**Foreground-Mask-Aware Relative Highlight Guidance**

它对应当前代码中已经成型、且最有说服力的这一条主线：

- foreground mask: 显式 alpha/mask 优先，白背景阈值只做 fallback
- relative highlight definition: 用局部相对亮度而不是纯绝对亮度定义高光
- quantile threshold: 只在前景内做自适应分位数阈值
- blur-only threshold estimation: 轻微高斯模糊只用于阈值估计，不直接改最终 score
- image-space highlight guidance: 保留图像级高光辅助分支，提供高信息量 RGB 监督

### 4.2 辅方法

下列内容更适合做辅助或附加实验，不应写成主贡献：

- `hybrid probe distillation`
- `latent-space highlight probe`
- `adamw_8bit`
- TF32 / benchmark / NaN guard / best checkpoint / early stop

它们的正确角色是：

- `hybrid probe distillation`: 效率变体
- `latent probe replacement`: 失败/对照实验
- `adamw_8bit` 与数值保护: 工程实现细节

## 6. 论文贡献口径

建议主贡献写成 3 条。

### 贡献 1

我们识别了 diffusion-based object relighting 在 specular / area-light 条件下的一个关键 failure mode：

- 高光监督对前景裁剪和绝对亮度阈值敏感
- 宽而软的高光波瓣会让 mask / weight map 变得不稳定
- condition image 的异常 lighting 会放大这一问题

### 贡献 2

我们提出一种 **foreground-mask-aware relative highlight guidance**：

- 有效前景内定义高光
- 在局部相对亮度域做 quantile threshold
- 仅用平滑图估计 threshold，最终 score 仍基于原始亮度
- 通过 image-space highlight guidance 提供高信息量辅助监督

### 贡献 3

我们建立一个更适合分析高光与跨域泛化的 object-relighting evaluation protocol：

- `official` 作为标准主基线
- `ecommerce` 作为产品域增强与目标域评估
- `3D-FUTURE` 作为跨域测试集

### 辅贡献

可以写进文中，但不要当主贡献：

- `hybrid probe distillation` 作为效率变体
- alpha/mask-priority 的前景监督实现
- 数据预检脚本与跨域数据协议

## 7. 数据策略

### 7.1 方法消融

**固定用 `official-1000`。**

原因：

- 正确 baseline 已经在这个数据协议下建立
- 这是与原始 `Neural Gaffer` 最公平的对照口径
- reviewer 最容易接受“在标准基线上做方法消融”

### 7.2 主模型训练

先用：

- `official-1000 + official-2000`

这条线负责回答：

- 方法在更大但同分布的数据上是否继续成立
- 提升是否不是只来自某个小规模训练偶然性

### 7.3 产品域增强

在第 7.2 步基础上，再做：

- `+ ecommerce-1000 balanced mix`
- `official+official_2000 -> ecommerce finetune`

建议写法：

- `balanced mix`: 通用模型增强
- `finetune`: 产品域特化模型

### 7.4 3D-FUTURE

当前阶段不建议并入主训练。

更合适的角色是：

- 第一阶段：`test-only cross-domain benchmark`
- 第二阶段：若渲染出 `800-1000` 个干净完整对象，再做附加训练实验

原因：

- 如果太早并入主训练，容易让 reviewer 质疑“改进来自更多数据还是来自方法”
- 先把它当 OOD test，更能证明方法本身的泛化能力

## 8. 实验矩阵

### 8.1 表 1：主方法消融

固定数据：`official-1000`

建议行：

1. original baseline
2. `+ foreground-mask-aware supervision`
3. `+ relative highlight definition`
4. `+ quantile threshold`
5. `+ blur-only threshold estimation`
6. `+ image-space highlight guidance`
7. `+ full main method`

指标：

- PSNR / LPIPS / SSIM
- `uu / us / ra / tu / train`

### 8.2 表 2：训练数据策略

建议行：

1. `official-1000`
2. `official-1000 + official-2000`
3. `official-1000 + official-2000 + ecommerce-1000 balanced mix`
4. `official-1000 + official-2000`, then `ecommerce-1000 finetune`

目的：

- 把“方法效果”和“数据扩充效果”拆开
- 说明 `ecommerce` 是目标域增强，而不是 baseline 混乱来源

### 8.3 表 3：跨域泛化

训练建议先固定为主模型。

测试：

1. official held-out
2. ecommerce held-out
3. 3D-FUTURE held-out

目的：

- 证明方法不是只在单一训练域有效
- 让 `3D-FUTURE` 成为有说服力的 cross-domain test，而不是训练噪声源

### 8.4 表 4：效率变体

建议只放 2 到 3 行：

1. main image-space method
2. hybrid probe distillation
3. pure latent probe replacement

指标：

- peak VRAM
- steps/hour
- `uu / us / ra`

作用：

- 明确告诉 reviewer：probe 系列是效率变体，不是主方法

## 10. 不建议现在继续做的方向

在当前投稿窗口内，不建议继续开下面这些方向：

- `Specular-Diffuse` 显式双路解耦架构
- `Light-Probe Conditioned Diffusion`
- 大规模 backbone 重写
- 新的物理分解分支

原因：

- 它们都会把当前已经成型的论文主线打散
- 风险远高于收益
- 这些更像新项目，而不是投稿前最后一轮补强

## 11. 建议的论文结构

候选 1：

**Foreground-Mask-Aware Relative Highlight Guidance for Robust Object Relighting**

候选 2：

### 11.2 摘要骨架

建议摘要结构：

1. 任务背景：diffusion-based object relighting 很有效，但 specular / area-light 下存在高光监督失稳

4. 关键机制：relative highlight、foreground quantile threshold、blur-only threshold estimation、image-space guidance
5. 实验：在 official、ecommerce、3D-FUTURE 上验证
6. 结论：主 held-out 泛化更强，产品域和跨域泛化更稳
