不是只写作叙事，准确地说是“论文叙事 + 方法定义 + 数据协议 + 实验证据”要一起收拢。  
如果只是写法变了、但实验和协议没变，那不算升级；如果你把方法、数据和评估都围绕这三点重组，它就会从“训练优化”变成“可投稿的问题定义”。

**这三句话具体指什么**
- `specular / area-light failure mode 的针对性方法`：论文不再泛泛地说“我们提升了 relighting”，而是明确说“现有 object relighting 在宽而软的高光、随机面光源条件下容易失败，我们的方法专门修这个失败模式”。这需要你在实验里专门放 `random_area_light_condition`、宽高光案例和 failure analysis。
- `foreground-mask-aware 的训练原则`：这不是一句包装语，而是一个清楚的方法原则。
  具体就是：高光定义、quantile threshold、highlight loss、指标统计，都只在有效前景内做；显式 alpha/mask 优先，白背景阈值只做 fallback；而且这个原则不增加推理复杂度。
- `ecommerce / official / 3D-FUTURE 的跨域 benchmark`：不是说三个数据都混训练，而是定义清楚“在哪个域训练、在哪个域测试”，让论文能回答“方法是不是只对单一数据域有效”。

所以，**是叙事上的升级，但必须对应真实的方法和实验设计**。

**我建议的投稿口径**
主方法不要写 `hybrid probe distillation`。  
主方法写成：

`Foreground-Mask-Aware Relative Highlight Guidance for Robust Object Relighting`

你现在更像一篇论文的核心，是这条：
- 显式 foreground mask 优先
- 局部相对亮度定义高光
- 前景内 quantile threshold
- blur 只用于 threshold estimation
- image-space highlight guidance

`hybrid probe distillation` 更适合做辅方法或效率变体。

**建议的论文结构**
1. `Introduction`
   先讲 object relighting 的价值，再指出一个具体失败模式：specular / area-light 条件下，高光区域定义不稳，导致训练监督失真。
   最后给出三条贡献。

2. `Related Work`
   分三块写：
   object relighting / diffusion relighting
   highlight / specular-aware supervision
   cross-domain relighting evaluation

3. `Problem Setup and Data Protocol`
   明确定义任务：
   single-image object-centric relighting
   target lighting given by environment map
   specular / area-light robustness as key challenge  
   这里把 `official / ecommerce / 3D-FUTURE` 的角色说清楚。

4. `Method`
   这一节建议拆成：
   foreground-mask-aware supervision
   relative highlight measure
   quantile threshold with blur-only estimation
   highlight-guided image-space auxiliary loss  
   如果要放 `hybrid probe distillation`，放成最后一个小节，明确写它是 efficiency variant。

5. `Experiments`
   先主结果，再消融，再跨域，再效率。
   顺序不要反。

6. `Discussion and Limitations`
   诚实写：
   目前仍是 object-centric
   对真实复杂场景还没完全覆盖
   area-light 提升但不是所有 split 都单调更好

- 更合理的是把它当成：

**3D-FUTURE 怎么处理最合适**

- 你的方法不是只在自己训练域里涨
- 而且你没有把“更多数据”混成“更好方法”
