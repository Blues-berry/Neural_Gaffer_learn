## 1. 当前代码主线总结

根据 [neural_gaffer_training.py](/4T/CXY/Neural_Gaffer/neural_gaffer_training.py) 当前实现，论文主方法已经具备以下稳定模块：

1. foreground mask priority
2. white-background threshold fallback
3. foreground-only quantile threshold
4. blur-only threshold estimation
5. local relative highlight definition
6. image-space highlight guidance

效率侧辅助线已经具备：

1. latent highlight probe
2. pure latent replacement
3. hybrid probe distillation

因此论文叙事上应明确分成两条线：

- 主效果线：`foreground-mask-aware relative highlight guidance`
- 辅效率线：`latent probe / hybrid distillation`

## 3. 论文表格应该怎么写

### 3.1 主方法消融表

推荐标题：

`Current evidence-aligned ablation on official-1000`

推荐说明：

- 这张表记录当前仓库中已经完成的关键方法阶段
- 它反映“方法线如何演化到当前版本”
- 它不是最终严格单因素 ablation
- 最终投稿前需补 1-factor clean ablation

### 3.2 为什么不能直接假装成严格消融

原因很明确：

- `jbhdfvfc` 同时含有 `q88 + fg0.96 + warmup`
- `spuru5qy` 在其基础上又叠加了 blur-only threshold estimation
- `fi04f78e` 进一步叠加了 local relative highlight

所以当前更诚实的写法是：

- 先把现有结果写成“阶段性证据表”
- 再把缺失的 clean ablation 作为补实验任务

## 4. 还需要补的 clean ablation

以下是当前最值得补、而且最符合代码逻辑的严格单因素实验：

1. baseline `7cn19b1e`
2. `+ foreground-mask-aware supervision only`
3. `+ foreground quantile threshold`
4. `+ blur-only threshold estimation`
5. `+ local relative highlight`
6. `+ image-space highlight guidance`
7. `+ full main method`

为了避免训练预算不一致引入解释噪声，建议：

- 统一数据协议：`official-1000`
- 统一训练步数：建议 `40k`
- 统一随机光照概率：`0.4`
- 除目标变量外，其余配置全部固定

### 4.1 现在真正还必须继续补的主线消融

结合当前代码开关、已有 run 和论文主叙事，投稿前最应该继续补的不是“所有能想到的开关”，而是下面这 5 个主线单因素实验：

1. `baseline -> + image-space highlight guidance`
2. `+ foreground-mask-aware supervision`
3. `+ foreground quantile threshold`
4. `+ blur-only threshold estimation`
5. `+ local relative highlight`

原因是这 5 步正好对应当前论文方法章节里的 5 个核心论点：

- image-space highlight branch 是否必要
- foreground mask priority 是否真的比白背景启发式更稳
- foreground quantile threshold 是否优于固定阈值
- blur-only threshold estimation 是否能稳定 soft highlight
- local-relative highlight 是否真的提供了更合理的高光定义

换句话说，真正缺的不是“再跑更多版本”，而是把这 5 个论点拆成 reviewer 能接受的单因素证据链。

### 4.2 哪些实验虽然相关，但不应该继续占主线预算

以下几类实验可以保留为附录、补充材料或 rebuttal 备选，而不建议继续作为正文主线消融：

1. `warmup only` 单独消融
2. `random_lighting_condition_prob` 的概率扫参
3. `highlight_gamma / min_threshold / max_threshold` 这类超参扫参
4. `relative_mode=ratio` 的替代定义
5. `latent probe / hybrid probe / replacement` 再细分更多变体
6. `use_highlight_weighted_loss` 的 latent/noise-space 重加权

原因：

- 这些项更像训练稳定性技巧、效率变体或超参选择
- 它们不能直接支撑论文当前最核心的方法论点
- 继续深挖会明显挤占 clean ablation 和跨域实验预算

### 4.3 推荐的最小 clean ablation 矩阵

如果按“最小但足够投稿”的标准，建议最终只保留下面 6 行：

1. `Baseline`
2. `+ Image-space highlight guidance`
3. `+ Foreground-mask-aware supervision`
4. `+ Foreground quantile threshold`
5. `+ Blur-only threshold estimation`
6. `+ Local-relative highlight (Full main method)`

这里有一个很关键的现实判断：

- 当前已有 `qju56ygl / jbhdfvfc / spuru5qy / fi04f78e` 只能算阶段性证据
- 它们不能直接充当严格 clean ablation，因为步数和叠加项并不完全一致
- 如果 clean ablation 统一按 `40k` 跑，那么 baseline 与 fixed-threshold image-space 也最好补一个同预算版本

因此，从实验排期角度看，真正还要继续的 clean ablation 数量可以理解为：

- 如果接受旧 baseline 作为锚点：至少还要补 4~5 条
- 如果要求整张 clean ablation 表完全同预算：需要补 6 条整齐矩阵

### 4.4 建议的具体执行顺序

按论文收益 / 风险比排序，最推荐的执行顺序是：

1. `baseline 40k`
2. `+ image-space fixed-threshold 40k`
3. `+ foreground-mask-aware 40k`
4. `+ quantile q=0.88 40k`
5. `+ blur sigma=1.0 40k`
6. `+ local-relative difference, k=15 40k`

这样做的好处是：

- 每跑完一条，就能直接补齐 clean ablation 表的一行
- 一旦时间不够，前 4~5 条也足以支撑正文主结论
- 最后一条 local-relative 可以自然作为方法最终版收口

### 4.5 当前最不建议继续浪费时间的方向

从投稿优先级看，下面这些方向现在应明确降级：

1. probe 系列继续细调到超过主方法
2. 试图把 `random-area` 再单点刷高但牺牲 `uu/us`
3. 提前把 `3D-FUTURE` 并入训练再做混合解释
4. 在没有 clean ablation 的前提下继续扩展更多主方法小变体

更直白地说：

- 现在最大的短板不是“还没有更多花样”
- 而是“核心方法还缺 reviewer 一眼能看懂的单因素证据链”

## 6. 图示展示方式建议

### 6.1 图 1：问题定义图

目标：

- 让审稿人一眼看到 baseline 的失败模式

建议布局：

- 一行 5 列：input / target lighting / GT / baseline / ours
- 额外放 2 个 zoom-in crop

建议选例：

- `ra` split 中宽而软的高光
- 白背景边缘高光
- condition image 光照偏置明显的样本

### 6.2 图 2：方法原理图

目标：

- 解释主方法的 5 个模块如何串联

建议模块：

1. input object and target light
2. foreground mask priority
3. local relative highlight computation
4. blur-only quantile threshold estimation
5. image-space highlight guidance

右下角可加一个虚线框：

- optional latent probe / hybrid distillation

这样可以明确它不是主贡献主体。

### 6.3 图 3：official held-out 对比图

建议布局：

- 3 行：`uu` / `us` / `ra`
- 6 列：input / target env / GT / baseline / ours / crop

建议强调：

- highlight boundary
- broad soft highlight lobe
- glossy region continuity

### 6.4 图 4：cross-domain 对比图

建议布局：

- 3 列：`official` / `ecommerce` / `3D-FUTURE`
- 每列放 baseline vs ours
- 每个对象配 1 个局部高光放大框

这样可以更直接展示“不是只在一个数据域里有效”。

### 6.5 图 5：效率图

建议布局：

- 左侧：image-space / hybrid / latent replacement 的视觉结果
- 右侧：一个小柱状图，画 `peak VRAM` 和 `steps/hour`

作用：

- 让 hybrid 的价值一眼能看懂
- 避免审稿人误以为 probe 是主方法

### 6.6 图 6：diagnostic 图

建议展示：

- foreground mask
- threshold map
- highlight score
- final prediction

这张图最适合放 supplementary，也可以视版面情况压缩到正文。

### 6.7 图 7：failure cases 图

建议展示：

- mask 不准时的方法失败
- 极端 broad highlight
- 跨域材质差异过大时的失败

作用：

- 提前回答审稿人可能的质疑
- 让论文显得更诚实、更完整
